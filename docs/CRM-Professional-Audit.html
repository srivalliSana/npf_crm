Headline. Communications infrastructure is genuinely strong — SMTP, SMS (7 providers), WhatsApp, RCS with template approval, and telephony (EasyGoIVR with click-to-call) are all fully wired, not stubs. Payments and lead-source integrations are real but incomplete (Razorpay works, PayU is UI-only; Meta/Instagram work, LinkedIn is UI-only with no backend route). Everything else that makes a CRM feel "enterprise-grade" — analytics/attribution, e-signature, video conferencing, a general-purpose developer API, 2FA, GDPR tooling, a workflow-rule builder, custom fields, audit trails on records, forecasting — is absent. The product is a strong operational lead-to-admission engine with a comms stack most CRMs charge extra for; it is not yet a platform in the Salesforce/HubSpot sense.

3Where to spend effort first

Grouped by real-world payoff versus build cost, not by category order above.

🟢 Quick wins — finish what's already 80% built

  • Give Ask CU AI (Anthropic) its own Integrations settings card — it's fully working but invisible to any Admin who doesn't already know the hidden config path
  • Add a real /api/webhooks/linkedin-leads route — the UI and webhook URL are already advertised, the backend just isn't there
  • Wire the PayU fields that already exist in the UI, or remove them if PayU isn't actually planned
  • Add restore documentation/tooling on top of the existing S3 backups — the hard part (getting data out safely) is already solved

🟡 Medium build — real gaps a growing team will hit soon

  • UTM capture + Meta Pixel/CAPI + GA4 wiring — you're already paying for ads; right now there's no way to measure cost-per-lead or cost-per-admission
  • Field-level audit trail on leads/applications — "who changed this and when" is one of the first things a compliance or ops review asks for
  • A merge-duplicates tool — create-time dedup is good, but duplicates from bulk imports/API sources will still slip through and need cleanup
  • Two-factor authentication — cheap to add (TOTP), meaningfully raises the bar against account takeover on Admin accounts

🔴 Major initiatives — only worth it once the above is done

  • A generic workflow/automation rule engine ("when X happens, do Y") — this is what would make the "digital ecosystem, not a database" pitch actually true across every module, not just payments
  • Custom fields + a report builder — real platform-tier features, but a significant schema/UI investment
  • A documented public API with proper key management — only worth it once there's an actual external system wanting to integrate
  • Enterprise SSO (SAML/Okta) — matters once you're selling into institutions with their own IT policy, not before
